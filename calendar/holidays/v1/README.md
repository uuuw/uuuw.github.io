# 时间规划局 · 中国大陆休假数据

本目录通过现有 GitHub Pages 网站提供公开、只读的年度放假与补班数据，无需独立服务器。当前已核实并发布 2026 年；未列入清单的年份视为暂无数据，不应推断为没有假期。

## 访问地址

- 版本清单：https://shijianguihuaju.cn/calendar/holidays/v1/manifest.json
- 2026 年：https://shijianguihuaju.cn/calendar/holidays/v1/2026-r1.json

## 数据含义

- `schemaVersion`：文件格式版本；不支持的版本应拒绝读取。
- `region: CN`：中国大陆全国性节假日安排，不包含个人排班、地方性假期或单位单独安排。
- `revision`：递增的数据修订号。
- `coverage`：本文件已经核对的公历日期范围，包含起止日期。日期字符串按日历格显示的年月日匹配，不应把日期键当作 UTC 时间戳转换导致跨日。
- `status: off`：官方公布假期范围内的休息日，显示“休”，包含该范围内的周末。
- `status: work`：调休补班日，显示“班”。
- 覆盖范围内未列出的日期不显示角标；普通周末、普通工作日不逐条收录。范围外或没有年度文件的日期属于未知，不能套用其他年份。
- `name` 是关联假期名称，不表示当天一定是节日本日。例如 2026-09-20 的补班归属国庆节。
- 节日、农历、节气与本数据分别处理。

2026 年数据依据国办发明电〔2025〕7号整理，共 33 个假期休息日、6 个补班日。来源与核对用的政府网站转载链接保存在年度文件 `sources` 中。

## 更新步骤

1. 以官方通知核对全年假期范围、补班日及跨年日期，不使用预测安排。跨年安排应同步检查相邻年度文件。
2. 新增版本化文件，例如 `2026-r2.json`，不要覆盖旧修订文件；更新年度 `revision`、`updatedAt` 和来源。
3. 检查日期有效、无重复、休息和补班不冲突，统计记录数。对最终发布文件的原始字节计算 SHA-256（包括换行），可使用 `shasum -a 256 文件名`。
4. 先发布年度文件并确认 HTTPS 可以下载，再更新 `manifest.json` 中的年度路径、修订号、记录数与校验值，同时递增清单修订号。保留清单中已有的其他年份。
5. 等待 GitHub Pages 部署完成，下载清单与年度文件，再次核对 JSON 和 SHA-256。修正错误时发布更高修订号的新文件，避免客户端因防止版本回退而忽略修复。

## App 接入约定（尚待实现）

App 内置已核实的年度文件作为保底，并将联网更新后的有效文件原子写入 App Group 共享目录，供 App 和小组件读取。优先使用相同年份较新且验证通过的本地修订，不让旧缓存覆盖新版内置文件。

App 打开时按间隔检查版本，可利用 HTTP ETag；没有更新则不重复下载年度文件。年度路径只允许本目录内的相对 JSON 文件名。下载需限制大小、超时与重试频率，并校验 SHA-256、格式、地区、年份、修订号、覆盖范围和记录数，验证全部通过后再替换缓存。SHA-256 用于完整性检查，不能代替 HTTPS 或来源身份验证。

网络失败、文件不存在或校验失败时保留最后一次有效缓存；没有缓存时读取内置数据。小组件不各自请求网络，数据更新后由 App 请求刷新。系统决定小组件实际刷新时间。

## 网站维护注意

网站由 Hexo 生成。以后重新生成或整站部署时，必须保留本目录；如果通过 Hexo 源项目生成，需将 `calendar/holidays` 纳入源项目的静态文件目录，避免被整站发布覆盖。

本次仅建立公开数据源，不包含 App 下载、缓存或日历 UI 的实现。年度数据仍需核对后人工发布，当前未启用自动抓取或自动更新任务。
